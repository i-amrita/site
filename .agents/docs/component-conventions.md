# Component conventions

Every component lives under `src/components/`. There are three folders with one rule each, plus generated code that the build owns.

| Folder | Holds | JS | Format |
|---|---|---|---|
| `astro/` | Our static components. No client JS, no state, no listeners. | No | `.astro` |
| `react/` | Our interactive islands and our wrappers around `ui/` primitives. Hydrated with `client:load` or `client:visible`. | Yes | `.tsx` |
| `ui/` | Vendored shadcn/ui output. Treated as granted-correct. | Yes | `.tsx` |

Current contents, as of this commit: `src/components/react/Providers.tsx` (island root) and `src/components/ui/` with `button`, `command`, `dialog`, `drawer`, `popover`, and `tooltip`. `src/layouts/Base.astro` is the only Astro layout. Keyboard, overlay, search, and theme components are planned and not written yet.

## Decision tree

1. Did `pnpm dlx shadcn@latest add <name>` produce it? Put it in `ui/`. Change it only by re-running the same CLI.
2. Does it wrap a `ui/` primitive and add our logic, props, or styles? Put it in `react/` and compose the vendored piece. Never edit the vendored file.
3. Is it static, with no `onClick`, no state, and no listeners? Put it in `astro/`.
4. Is it interactive and ours, not a wrapper? Put it in `react/`.
5. Is it generated by a tool (Paraglide output, `.astro/` types)? Do not edit it by hand. The build owns it.

Examples from the plan: `Navbar.astro` and `Footer.astro` are `astro/`. `Keyboard/` and `CmdK.tsx` are `react/`. `SearchModal.tsx` is `react/` because it wraps Pagefind and a `ui/` dialog. `ProjectsOverlay.tsx` is `react/` because it composes `ui/dialog.tsx` with a scroll container and cards.

## Vendored `ui/` rules

- Do not edit files in `src/components/ui/`. Re-running the shadcn CLI overwrites local edits.
- Do not lint or format `ui/`. `.oxlintrc.json` and `.oxfmtrc.json` both ignore `src/components/ui/**`. The lefthook pre-commit hooks exclude it too.
- If a `ui/` file fails lint, the fix is never in that file. Fix the wrapper in `react/`, or fix the CLI invocation.
- Do not refactor or reformat vendored code, even to satisfy a style rule.

Right pattern:

```tsx
// src/components/react/SearchModal.tsx (ours)
import { Dialog, DialogContent, DialogTitle } from '@/components/ui/dialog';
// wire to our URL state, Pagefind binding, and focus handling
```

Wrong pattern: adding project logic inside `src/components/ui/dialog.tsx`.

## Why there is no `ui/sonner.tsx`

shadcn's generated `sonner.tsx` imports `next-themes`, which this project does not use. It also fails under `exactOptionalPropertyTypes` (set in `tsconfig.json`). So the file was removed from `ui/`. Toasts now import `Toaster` from `sonner` directly inside `src/components/react/Providers.tsx`. If a toast wrapper grows, put it in `react/`.

## Islands and providers

Every island root is wrapped in `Providers` from `react/Providers.tsx`. It provides:

- `NuqsAdapter` from `nuqs/adapters/react`, so all islands share one URL emitter and stay in sync (see `url-state.md`).
- `TooltipProvider` from `ui/tooltip`.
- `Toaster` from `sonner`, positioned bottom-center.

`astro.config.mjs` registers `@astrojs/react` with `include: ['**/react/**', '**/components/ui/**']`. A new island folder outside `react/` will not hydrate unless it is added to that list.

## Styling rules

- Use semantic token classes only (see `tokens.md`).
- Use `cn()` from `src/lib/utils.ts` to merge class names. It wraps `clsx` and `tailwind-merge`.
- Home hero chips, navbar pill and keypad icons use `unplugin-icons` with the Phosphor set (`@iconify-json/ph`, `-light` variants). Import statically: `import Mail from '~icons/ph/envelope-simple-light'`, then `<Mail class="size-4" aria-hidden="true" />` (`className` in React). Vite registers one `jsx`/react compiler in `astro.config.mjs` (the `astro` compiler cannot coexist with it, so `.astro` files render the React icon statically with no `client:*`); types come from `src/env.d.ts`. Keypad icons map name to component in `Key.tsx`; no dynamic string imports. Overlays, CmdK, ProjectCard and `ui/*` still use `lucide-react` / `@lucide/astro`.

## Checklist for a new component

1. Pick the folder with the decision tree.
2. If it renders pixels, it goes through the UI loop (see `ui-loop.md`).
3. If it reads or writes state, bind it through `urlStateParsers` and add a row to `url-state.md`.
4. If it is an interactive island, confirm it is under `react/` and hydrated with a `client:*` directive.
5. Run `pnpm check`, `pnpm lint`, and `pnpm format:check` before committing.
